## tgproxy v1.7.2 — v1.7.1 复核收口（小 N 兜底 + 锁覆盖 + 文档对齐）

对应 v1.7.1 复核的 4 处口径问题与 3 条建议动作，全部落地。

### 1. 环境异常判定分级（P2：比例阈值在 3~4 源时退化）
- ≤2 源：仅全 0 时保护（小样本无法区分「源垃圾」与「环境异常」，保守）
- 3~4 源：放宽为「至多 1 个源有产出」——修复实测问题：4 源 3 零（75%）此前不保护、被换掉 3 个源
- ≥5 源：维持 80% 比例
- 验收场景实测：4 源 3 零 + 1 源 5 节点（75%）→ 保护、不换源、提示含占比

### 2. 锁覆盖补全（P3：表述过头的实底）
- `_lock` 升级为 **RLock**，`_update_source_health` 全程持锁（此前 health 锁外 load → 锁外 save，与设置保存线程存在毫秒级竞态窗口）——现在健康度读改写与活跃源变更对设置保存线程原子

### 3. README 两处口径改准（P2：文档漂移）
- 「全部活跃源同时 0 产出」→ 「分级比例（≥5 源 80% / 3~4 源至多 1 个有产出 / ≤2 源全 0）」
- 「在设置里手动重新保存」→ 「编辑 config.json 后重启」（桌面 UI 无源编辑控件，真实路径）
- 单源场景恒判环境异常的取舍显式写明

### 4. 发布说明措辞（P3）
- v1.7.1 正文「version bump 后重跑」已改为如实表述：「测试执行于 version bump 之前（Gradle 判定 UP-TO-DATE 复用结果，版本号不影响测试逻辑），APK 在 bump 后构建」
