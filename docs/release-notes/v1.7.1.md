## tgproxy v1.7.1 — v1.7.0 复核修复（宽恕可达性 + 比例判定 + 抽样保底 + 版本号对齐）

对应 v1.7.0 复核的五条行动清单，全部落地并验证。

### 1. 宽恕可达性（P1：此前桌面端用户碰不到）
- `set_proxy_list_urls` 重写为 **per-URL diff**：只宽恕本次新增的 URL；同时修复复核指出的副作用（新增源不再清掉在列源的健康历史）
- 读改写整体挪进 `_lock`（消除与刷新线程的写覆盖）
- **新增启动宽恕**：`main()` 启动时对 config.json 里的 URL 执行一次 `forgive_sources()`——用户手动编辑配置加回被停用的源，重启即重新观察

### 2. 换源保护改比例判定（P1：全 0 才生效）
- 0 产出占比 **≥80%** 即判环境异常（Telegram 封锁/门槛调严）：不累计零产出轮次、不停用、不补位
- 验收场景实测：5 源中 4 源 0 + 1 源 1 个节点 → 保护；对照组 4 正常 + 1 源长期 0 → 该源仍被停用
- notice 拼接改造：环境异常提示（含占比数据）与停用/补位文案可同轮共存

### 3. 抽样每源保底（P2：抽样稀释）
- 全局抽样（MAX_TOTAL=3000）时每个源先各留 **10 条**（SOURCE_SAMPLE_FLOOR）
- 实测：20 个 20 条的小源 + 3 万大池，抽样后 20 个小源无一被抽空（此前三连空概率 5.61%）

### 4. 版本号对齐（P2）
- 安卓 **versionCode=9 / versionName=1.7.1**（`aapt2 dump badging` 验证），此前 APK 错标 1.5.0
- 桌面 exe/zip 同步 v1.7.1

### 5. 桌面零测试（P3，评审观察的根因）
- 新增 `tgproxy/tests/test_source_health.py`：8 个用例固化本轮全部离线验证路径
  （两种停用原因、比例保护、单源劣化、_src 缺失保护、宽恕 per-URL diff、抽样保底）
- pytest 与直跑双运行器全绿（`python -m pytest tgproxy/tests -q` → 8 passed）

### 实测数据
- 安卓：8 类 / 51 用例 / 0 失败（JUnit XML 留档）；测试执行于 version bump 之前（Gradle 判定 UP-TO-DATE 复用结果，版本号不影响测试逻辑），APK 在 bump 后构建
- 桌面：8 个 pytest 用例全绿；实跑一轮 21 个 <1s 节点无回归
