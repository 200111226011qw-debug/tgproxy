## TGProxy Android v2.3.0

MTProto 节点从「一律未验证」改为**真握手校验**。这是安卓端第一次真正能判定 MTProto 节点——
在此之前它们不做任何实测，永远进不了可用列表。

### 新增：obfuscated2 真握手

现在直连节点发 64 字节 obfuscated2 头 + `req_pq_multi`，要求对端回一个**带我们随机 nonce 的
`resPQ`**（constructor `0x05162463`）。

判据从「端口能连上」变成「对端真的是 Telegram 出口」：透明代理、劫持设备、随便一个
acceptance server 都能让 TCP 连上，但伪造不出这个回包。

- 预算 `max(2s, 延迟门槛 + 1s)`，与桌面版 `mtproto_budget_for` 同源
- 失败分码（连接失败 / 超时 / 网络 / 协议 / secret 格式），日志里能区分「该换节点」和「该改配置」
- `TgGateStats` 仍只统计 SOCKS5 两关：MTProto 没有隧道关卡，混进去会让漏斗撒谎

### 修复：secret 只解析一次

`tg://proxy?...&secret=` 以前被解析两遍（解析器解一次、实测阶段再从 `link` 反解一次）。
百分号编码的 secret（如 `%3D%3D`）会在第二步变回原文，导致节点被误判失败。
现在解析阶段解好放进条目，实测直接用；`known_good` 同时落盘该字段，恢复后不会丢。

### 不变：`ee`（FakeTLS）仍记「未验证」

`ee` secret 尚未实现，这类节点记「无法判定」而**不计失败**——不会被连败拉黑。
桌面端同口径（`FAKETLS_UNSUPPORTED`）。等 Phase 1b 真正支持后再进闸门。

注意：`secret` 存在但格式非法仍计失败（两端一致），它和「缺 secret」是两回事。

### 测试

- 安卓 18 个测试类 / 161 例 × debug + release = **322 全绿**
- 与桌面版 `mtproto_handshake.py` **跨语言黄金向量对拍**：四密钥、加密 init 尾、加密请求帧
  逐字节相等；服务端响应向量解密后是合法 `resPQ`（帧长自洽、nonce 回显、`server_nonce` 正确）
- 变异自检 **7/7**：把实现改错（反向切片改顺序 / init 尾改明文 / 去掉 nonce 校验 / secret 错位 /
  通过记失败 / 无法判定记失败 / 解析器不传 secret）后，目标测试都会红

### 升级说明

签名证书与 `android-v2.2.1` **是同一把**（`CN=TGProxy`，证书 SHA-256 `6b022d5e…`），
可直接覆盖安装，**不需要卸载**，本地 known_good 不会丢。

### 校验

APK **不可字节复现**（dex 本身非确定、签名块含高熵数据），所以校验只能用发布物本身：

```
sha256   b95fc13fb83564c99651d7d921992ae4ad72218708aa1f007b880ef3010c369a
大小     11,890,667 B
```

下载后重算并与上面比对。用本地重新构建的产物比对会得到「不一致」的假警报——那不是发布坏了。

### 已知边界

- `ee` / FakeTLS 未实现（记未验证，不计失败）
- 未在真机连过 Telegram：沙箱没有到 Telegram 的出口，四个 DC 全部超时，这一步只能用户本机验
- 桌面 Phase 3 的镜像竞速尚未移植到安卓抓取层（目前是顺序回退）
