# 安卓版 v2.0.0 — 「不能用」根因修复 + TG 实测对齐 + 界面重做

## 为什么旧版「不能用」（雷电模拟器实机诊断结论）

在雷电模拟器实装 v1.7.1 实测：点「刷新」后 **12 分钟仍未完成一轮刷新**（全程只有转圈，无任何进度），且旧版为 TCP-only 测试——即使测完，"可用"节点也未必能上 Telegram。两个根因：

1. **测试规模 × 超时不匹配**：3000 条候选 × 5s 超时 ÷ 64 并发，且每个 host 的 DNS 解析发生在超时计时之外，实测永不收敛；
2. **无 TG 实测、无延迟门槛**：TCP 通 ≠ Telegram 可用，也没有桌面版的 1000ms 硬门槛。

## v2.0.0 修复（与桌面版测试口径逐项对齐）

- **TG 实测双闸**（新类 `TelegramGate`，SOCKS5 握手字节序与桌面版 `_socks5_connect` 逐项一致）：
  - 第一关：经代理 CONNECT Telegram 数据中心 `149.154.167.51:443`，往返毫秒即节点延迟；
  - 第二关：经代理 CONNECT `desktop.telegram.org` + TLS 证书校验 + HTTP 状态行（GET，验证全链路可用无劫持）；
  - 两关串行共享单节点 20s 总预算（单关 8s），并发 96；仅 SOCKS5 参与，MTProto 记「未验证」。
- **TCP 预筛提速**：128 并发（对齐桌面版 150），仅 TCP 存活者进入 TG 实测。
- **1000ms 延迟门槛**：仅保留经代理到 TG 数据中心往返 ≤1000ms 的节点（固定值，与桌面版默认一致）。
- **分阶段进度卡**：刷新中显示「抓取数据源 i/N → TCP 预筛 i/N → TG 实测 i/N」+ 进度条，不再是盲转圈。
- **known_good 沉淀**（开关默认开）：上轮验证通过的节点存入应用私有目录，下轮优先复测；**启动即展示上轮可用节点**，无需等待刷新；关闭后沉淀文件保留但不再读取/写入。
- **本轮 0 达标保护**：已有列表时保留上一轮列表并提示门槛，不白屏。
- **五项统计**（口径契约：前四项之和 = 本轮测试总数）：验证保留 / 未验证 / TG 未过（含超门槛）/ TCP 不通 / 已排除。

## 界面重做

Telegram 品牌深色主题（#17212B 背景 + #2AABEE 主色，浅色主题保留）；卡片行 = host:port 等宽粗体主标题 + 类型 · 地区 · ISP 元信息 + 右侧延迟胶囊（<1000ms 绿 / <3000ms 橙 / 其余红 / 未测 灰）+ 行内复制 / 分享；**整卡点击直接唤起 Telegram「添加代理」**（SOCKS5 走 `tg://socks` 深链）；五枚统计胶囊横滑条；known_good 开关在控制卡内。

## 实机验证（雷电模拟器 14，Android 9 ×64）

| 指标 | v1.7.1（旧） | v2.0.0（新） |
|---|---|---|
| 一轮刷新 | 12 分钟未完成（终止观察） | 约 6.5 分钟完成全管线 |
| 刷新反馈 | 仅按钮转圈 | 三阶段进度卡（抓取→TCP→TG，逐条计数） |
| 测试口径 | TCP-only | TCP 预筛 + TG 双闸 + ≤1000ms |
| 重启到看到可用节点 | 等整轮刷新 | known_good 即时展示 |
| 本轮实机产出 | 不可用 | 1 个 929ms 节点（≤1000ms 保留） |

## 测试

- JVM 单测：**10 类 74 例 × debug/release 双变体 = 148 例全绿**（`gradle test --rerun-tasks` 实跑）；
- 新增 `TelegramGateTest`（SOCKS5 握手字节序 / TLS GET / 状态行 / 拒绝 / EOF / 预算不足放弃第二关）、`KnownGoodStoreTest`（读写往返 / 开关两端 / 损坏回退 / 坏条目跳过）；
- 修复单测稳定性：全部协程共用同一测试调度器（消除跨线程派发竞态导致的假死循环）。

## 升级说明

- 版本：versionCode 10 / versionName 2.0.0（debug 签名，覆盖安装需先卸载或同签名）；

- 源自动体检换源与爬虫模式仍为桌面版功能，安卓版数据源列表与桌面版一致（固定精选 5 源 + jsDelivr 镜像回退）。
