## tgproxy v1.3.0 — TG 实测选节点：只保留真正能连 Telegram 的节点

### 核心变化：两阶段实测
1. **TCP 测活**（150 并发）：剔除死节点（此前唯一的一步）
2. **TG 实测**（新增，100 并发）：对存活节点逐一经 SOCKS5 代理
   - CONNECT Telegram 数据中心 `149.154.167.51:443`（Telegram 客户端收发消息实际走的线路）
   - 全链路访问 `desktop.telegram.org`（TLS 证书校验 + HTTP，顺带排除透明代理劫持）
   - **两关都过的节点才留在列表里**——加了就能用，不再出现「列表里有但 Telegram 连不上」

### 实测数据（国内网络，3 轮 × 3000 条候选）
| 指标 | 数值 |
|---|---|
| TCP 存活 / 轮 | ~810-840 |
| TG 实测通过 / 轮 | 49~66（仅约 6%！） |
| 三轮全部稳定通过 | 3 个 |
| 全链路延迟 | 最快 1.7s，中位 10.5s |

**什么样的节点能通**（138 个验证通过节点的地理分布）：地区高度分散——荷兰 6、美国 5、香港 4、法国/德国/日本各 3、韩国/芬兰/新加坡各 2；ISP 分布于 Contabo、Hetzner、Google Cloud、Korea Telecom、UCloud 等。结论：**能不能通与国家关系不大，关键看节点是否开放 SOCKS5 且未封 Telegram**——所以自动重测比挑地区更重要。三轮全稳的最快节点：`183.106.215.208:1080`（韩国 KT，~2.2s）。

### 界面
- 列表按 TG 实测延迟升序，延迟列显示的就是经代理访问 Telegram 的往返耗时
- 统计卡：可用（TG 实测通过）/ TCP 通但 TG 不通 / 不通已剔除 / 已排除
- 「添加到 Telegram」按钮不变：唤起 Telegram Desktop 直接弹出添加窗口
