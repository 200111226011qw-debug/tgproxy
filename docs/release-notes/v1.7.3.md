## tgproxy v1.7.3 — v1.7.2 复核收口（文档对齐 + N=4 回归用例）

对应 v1.7.2 复核的「三项声称未落地」与流程建议。**本提交 diff 含 3 个文件，与下述各项一一对应**（README.md / tgproxy/README.md / tgproxy/tests/test_source_health.py）。

### 1. 根 README 体检段改准（复核 4.1）
- 「全部活跃源同时 0 产出」→ **分级比例**：≥5 个源时 0 产出占比 ≥80%、3~4 个源时至多 1 个源有产出、≤2 个源时仅全部为 0
- 「在设置里手动重新保存」→ **真实宽恕路径**：桌面界面不提供源编辑，编辑 `config.json` 的 `proxy_list_urls` 加回被停用的源后**重启**即视为「重新观察」
- 取舍显式写明：≤2 个源时无法区分「源变垃圾」与「环境异常」，单源长期 0 产出会恒判环境异常而不换源

### 2. 桌面 README 补齐（复核 5.1）
- 删除重复的「爬虫模式」条目（`:8`/`:14` 两条留一）
- 新增「源自动体检与换源」「known_good 沉淀」两节——此前 zip 用户读到的说明书完全没有这些功能描述

### 3. N=4/75% 回归用例（复核 4.2）
- `test_source_health.py` 新增 `test_four_sources_three_zero_protected`：4 源 3 零（75%）+ 1 源 5 节点 → 判环境异常、不换源（v1.7.2 修复场景的回归守卫）
- 用例需显式 `set_proxy_list_urls`（否则 active 会落在 5 个默认源上）
- docstring 用例计数由「11」修正为实际值；现共 **9 个用例**，pytest 与直跑双运行器全绿

### 4. v1.7.1 发布说明订正的说明（复核 4.3）
v1.7.1 正文经 API 复核**已是订正后状态**（「测试执行于 version bump 之前（Gradle 判定 UP-TO-DATE 复用结果…）」，原句不在）。复核报告读到原文可能取自缓存快照；当前以 API 实拉内容为准。
