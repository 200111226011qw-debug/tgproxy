## tgproxy v1.5.0 — 评审修复版（P0 三项 + 安全加固 + known_good 沉淀）

> 本版对应 2026-10-25 三方评审（产品/代码、安全、工程质量）的行动清单，21 条发现中已修复 15 条。

### P0（正确性与构建）
- 安卓本次未发版（versionCode=6 / versionName=1.4.1 保持）；主分支已在后续提交把版本号对齐 v1.5.0（versionCode=7 / versionName=1.5.0）
- **修复断网清空列表**：本轮 0 达标（含全源抓取失败）时保留上一轮列表，兑现 README「失败时保留旧列表」承诺（安卓端本就正确，桌面端现已一致）

### 安全
- 全部 POST 接口增加**同源校验**：显式拒绝 `Origin: null` 与 `Sec-Fetch-Site: cross-site`，堵住跨站改写数据源的投毒链路（`/api/refresh` 一并覆盖）
- **移除抓取的 SSL 免验证降级兜底**（防中间人投毒代理列表；安卓端本就未移植此兜底）
- `crawl_extract` 捕获 `RecursionError`（深层嵌套 JSON）；`refresh()` 异常兜底写入 `_error`，刷新线程不再静默死亡
- MTProto 深链统一收敛为 `tg://` 前缀（防 `https://t.me/proxy?...` 被 startfile 打开浏览器）

### 正确性
- TG 实测改回**每节点串行两关**（DC → 站点），消除对同一免费代理并发双连接造成的假失败——实测同一口径下可用节点 15 → 22~25 个
- **MTProto 未验证节点不再计入「可用」**：新增「未验证」统计卡 + 列表内标注，`available` 一词名副其实
- 每节点 TG 实测 **20s 总预算 deadline**（逐步骤收紧 socket 超时），防个别节点拖垮整轮
- `tg_failed` 含超门槛节点，四项统计之和 = 本轮测试总数

### 产品（评审建议采纳）
- **known_good.json 沉淀**：本轮验证通过的节点持久化，下轮优先复测并保留；全源失败时沉淀节点仍可复测兜底——实测断网场景保留 8 个仍可用节点

### 文档对齐（声明—证据）
- 删除「核心功能（两版本一致）」的失真表述，如实标注 TG 实测/门槛/爬虫为桌面版功能
- `tg://socks` 深链说明同步至两份平台 README；着色阈值三处统一为 <1s 绿 / <3s 橙
- `qa_parser_vectors.py` 去掉过期绝对路径（实测可运行）；安卓测试并发 20→64（消除「12.5 分钟一轮」）

### 实测（本轮，国内网络）
- 25 个可用节点全部 <1s（最快 434ms），四项统计之和 = 3000 测试总数
- 断网演练：全源失败 → known_good 复测兜底保留 8 个仍可用节点，提示语准确
- CSRF 演练：恶意 Origin 403 / Origin null 403 / 本机 Origin 200 / 无 Origin 200
