## tgproxy v1.4.0 — 延迟门槛 1000ms + 爬虫抓取模式 + 池子大换血

### 池子大体检（13 个候选源统一标准打分：抓取 → TCP → TG 两关实测）
| 入选源 | TG 通过率（存活节点） |
|---|---|
| **hideip.me**（zloi-user） | **~45%** |
| proxyscrape API | ~24% |
| monosans/proxy-list | ~25% |
| TheSpeedX/PROXY-List | ~7% |
| watchttvv（原始源） | 小池含元数据 |

**剔除垃圾池**：hookzof、proxifly、zevtyardt（各 2~7 万条大列表，体测 TG 通过率 ≈ 0）、jetkai、mmpx12。

### 延迟门槛（按你的要求：1000ms 以下）
- TG 延迟口径改为「**经代理到 Telegram 数据中心的往返**」——与 Telegram 客户端实际线路一致，最贴近使用体感
- 默认只保留 **<1000ms** 的节点，不达标直接剔除（界面「TG 延迟上限」可调 500~60000ms）
- 分档着色：<1s 绿 / 1~3s 橙 / 更高红
- **实测（国内网络）**：1500+ TCP 存活节点中，15 个同时通过两关且线路往返 <1s——最快 427ms、中位 775ms，**列表全员绿灯**，带国家元数据（美国/塞舌尔/韩国/日本…）

### 爬虫抓取模式（新增）
需要爬网页的 IP 源现在也能用：按行解析几乎无产出时，自动走通用抽取——
- 任意 HTML 页面中的 `ip:port` 对（表格站、脚本变量等）
- JSON API 的 `ip/port` 字段（如 geonode：`sort_by=latency` 按延迟排序的免费代理接口）
- `host:port|国家` 行格式
误报由 TG 实测自动过滤。已实测 socks-proxy.net（可爬，今日产出 0）、geonode（可爬，今日产出低）——爬虫模式已内置，任何页面源粘进设置即可用。
