## tgproxy v1.7.0 — v1.6.0 复核修复（P0 崩溃路径 + 换源保护 + 全量测试与 APK 实证）

### P0｜known_good 兜底不再崩（复核发现的可复现崩溃）
- 上一轮的源自动体检让 known_good 兜底路径踩了 `KeyError: '_src'`：当某节点从所有源列表消失但**仍然可用**（正是兜底该生效的场景），整轮刷新抛异常中止，且每 10 分钟复现
- 修复：归因前对 `_src` 缺失做保护，known_good 补入的节点跳过逐源归属（不属于任何源）

### P1｜两道换源保护（防不可逆改写用户的源）
1. **全局 0 产出判定**：所有成功抓取的源本轮 TG 验证产出全为 0 → 判为环境异常（Telegram 封锁 / 延迟门槛调严），本轮不累计零产出轮次、不停用、不补位，UI 提示「疑似网络/门槛问题，已暂停自动换源」。修复前：模拟 30 轮全局 0 产出会把 5 个用户源**全部永久换掉**
2. **手动加回 = 宽恕**：在设置里重新保存被停用的源，自动清除其停用标记与历史（重新观察），不再出现「加回当轮就被再停一次、用户无法恢复」的死局

### 其他
- `FETCH_MAX_SOURCES` 8 → 20，与 `MAX_PROXY_LIST_URLS` 对齐（此前用户配的第 9~20 个源既不抓取也不体检）
- README 补充体检两道保护的说明

### 安卓（本轮重点：全量测试与 APK 实证）
