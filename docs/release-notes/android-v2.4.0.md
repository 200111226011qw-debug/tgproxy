## TGProxy Android v2.4.0

抓取层从「顺序回退」升级为「单源镜像竞速」+ 完整性下限 + `callTimeout` 硬上限。
这一版主要解决「慢」和「静默失败」两个问题，并补上了抓取超时的真实边界。

### 新增：单源镜像竞速

「直连失败才回退镜像」的顺序逻辑，改成直连 + 3 个 jsDelivr 镜像**错峰并发**、
首个通过完整性校验的候选胜出、其余取消：

- 错峰 `index × 250ms` 依次发射，避免瞬间打满
- 落败候选 `call.cancel()` 真断连接，不在后台把整份列表下完（手机上流量是实打实的）
- 全局候选并发上限 `FETCH_RACE_MAX = 8`（有意低于桌面 64：20 源 × 4 候选峰值 80 条连接，手机顶不住）
- 全部失败时报错带各自原因，能分清是哪个源挂了

### 新增：完整性下限（竞速的安全网）

单候选响应要求 **≥ 64 字节**且含至少一条非注释行，否则判失败。
没有它，竞速会让「直连返回 0 字节（CDN 缓存穿透 / 上游截断）」更快胜出，整轮零节点。

### 修复：抓取超时对齐 + callTimeout 硬上限

- 单候选抓取超时 15s → **8s**，并补 `callTimeout(8s)`（覆盖 DNS+连接+写+读整段）。
  之前只有 `readTimeout`（只管单次读），慢速滴流能让单候选无限占着一个并发槽。
- 说明：安卓 8s 是**有意紧于**桌面「整场竞速 15s 总预算」（不是「对齐」），
  换来配满 20 源的最坏情况可控（见下）。

### 最坏情况（两个方向，一起看）

| 场景 | 旧（源内顺序） | 新（竞速 + cap 8） |
|---|---|---|
| 默认 5 源（20 候选） | 60s | **24s** ✅ |
| 配满 20 源（80 候选） | 60s | **80s** ❌ |

「变快」只在默认配置成立；配满 20 源且网络全挂时会变慢。这个反方向是刻意取舍
（cap 8 保热控），不是 bug。前提是 `callTimeout` 已落地——没有它这些数算不出来。

### 升级说明

签名证书与 `android-v2.3.0` **是同一把**（`CN=TGProxy`，证书 SHA-256 `6b022d5e…`），
可直接覆盖安装，不需要卸载，本地 known_good 不会丢。

### 校验

APK 不可字节复现（dex 本身非确定、签名块含高熵数据），校验只能用发布物本身：

```
sha256   6a253476b9bddc4b4abb512b314b9d0979659a36e4d513c66f9913536948720b
大小     11,890,671 B
```

下载后重算并与上面比对。用本地重新构建的产物比对会得到「不一致」的假警报——那不是发布坏了。

### 已知边界

- `ee` / FakeTLS 未实现（记未验证，不计失败）
- 未在真机连过 Telegram：沙箱没有到 Telegram 的出口，这一步只能用户本机验
- 桌面 `Age`/freshness 面板与 `via_mirror` 胜负上报未移植（安卓无源面板）
